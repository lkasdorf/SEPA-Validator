# camt.053 from a Payment File: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From a selected pain.001 or pain.008 file, write camt.053.001.08 statements next to it, as if the bank had booked the file. There is one statement per account and booking day, with the days chained. The new statements are appended to the file list and validated.

**Architecture:**
- A pure Rust module, `statement_gen.rs`, parses the payment file into booking groups and renders the camt.053 XML strings.
- `commands.rs` adds two IPC commands:
  - a preview, which reports what would be generated or why the file can't be booked;
  - a generate command, which picks collision-free target names, guards each one with `check_export_path`, and writes them with `create_new`.
- The Svelte frontend adds three things:
  - a dialog;
  - a viewer-bar button;
  - an append mode for the validation flow.

**Tech Stack:** Rust (quick-xml 0.36, libxml for the local XSD test), Tauri v2 IPC, Svelte 5 + TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-11-07-camt053-from-payment-file-design.md`

## Global Constraints

- Output namespace: `urn:iso:std:iso:20022:tech:xsd:camt.053.001.08`, root `BkToCstmrStmt`.
- Only EUR is booked. The account `Ccy` is `EUR`.
- Every bank-assigned ID starts with `SYNTH-`. The servicer `FinInstnId/Nm` is `SYNTHETIC TEST BANK`.
- `AddtlStmtInf` and every `AddtlNtryInf` read `Synthetic booking generated by SEPA Validator from <source file name>`, truncated to 500 characters.
- Amounts use `plausibility::Amount`, never floats. The opening balance crosses IPC as a string.
- The default opening balance in the dialog is `10000.00`, shown with the label "EUR".
- File names:
  - one account: `<stem>_camt053_YYYYMMDD.xml`;
  - several accounts: `<stem>_camt053_<last4 IBAN>_YYYYMMDD.xml`;
  - on a clash, `_1`, `_2`, … before `.xml`. Never overwrite.
- No `.xml`/`.xsd` committed outside `app/src-tauri/tests/fixtures/`. Test inputs are inline strings in Rust tests.
- Test data is synthetic: invented names, and IBANs for which `plausibility::iban_is_valid` is true.
- CI gates:
  - `cargo fmt --check`;
  - `cargo clippy --all-targets -- -D warnings`;
  - `cargo test`;
  - `npm run check`;
  - `npm test`.
- Commit format: `type(scope): summary`. Each commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Several PmtInf blocks with the same account and date** must merge into one statement with several entries, not into two files. *Test:* `same_account_same_day_merges` in Task 2.
2. **pain.001.001.09 nests the date** (`ReqdExctnDt/Dt` or `/DtTm`), while .03 writes it as plain text. Both must give the same booking day. *Test:* `date_forms_03_and_09` in Task 1.
3. **XML special characters in copied text** (`&`, `<` in names or Ustrd) must be escaped, or the output is not well-formed. *Test:* `escapes_copied_text` in Task 2.
4. **A negative opening balance, or one that crosses zero,** must write `CdtDbtInd` DBIT with an unsigned `Amt`, and the checks must still pass. *Test:* `negative_opening_chains` in Task 2.
5. **A generated name that already exists**, for example after running Generate twice, gets `_1`, `_2`, and the existing file stays byte-identical. *Test:* `second_run_does_not_overwrite` in Task 3.

### Task 2: Render camt.053.001.08 statements

**Files:**
- Modify: `app/src-tauri/src/statement_gen.rs`

**Interfaces:**
- Consumes: `Payment`, `Block`, `Tx` and `parse_payment` (Task 1); `statements::check`, `plausibility::check`, `plausibility::today` and `Amount`.
- Produces:
  - `pub(crate) struct Generated { pub iban: String, pub date: String /*YYYY-MM-DD*/, pub xml: String }`
  - `pub(crate) fn generate(xml: &str, source_name: &str, opening: Amount, today: &str, now: &str /*YYYY-MM-DDTHH:MM:SS*/) -> Result<Vec<Generated>, Vec<String>>`. The result is ordered by account (first appearance in the file), then by date ascending.
  - `pub(crate) fn now_utc() -> String`, built from `SystemTime` and `civil_from_days`.
  - `#[derive(Serialize)] #[serde(rename_all = "camelCase")] pub struct StatementPreview { pub kind: String /*"pain.001"|"pain.008"*/, pub accounts: u32, pub days: u32 /*distinct dates*/, pub statements: u32, pub transactions: u32, pub problems: Vec<String> }`
  - `pub(crate) fn preview(xml: &str, today: &str) -> StatementPreview`. On a parse `Err`, every count is 0 and `problems` holds the reasons.

**XML layout** (element order fixed by the XSD; optional elements are left out when the source has no value):

```
Document > BkToCstmrStmt >
  GrpHdr: MsgId (SYNTH-<now compact>-<last4>-<seq 3 digits>), CreDtTm (now)
  Stmt:
    Id (SYNTH-<YYYYMMDD>-<last4>-<seq>), ElctrncSeqNb (1..n per account), CreDtTm (now)
    FrToDt: FrDtTm <date>T00:00:00, ToDtTm <date>T23:59:59
    Acct:
      Id/IBAN, Ccy EUR, Ownr/Nm
      Svcr/FinInstnId: BICFI when known, then Nm SYNTHETIC TEST BANK
    Bal OPBD and Bal CLBD:
      Tp/CdOrPrtry/Cd, Amt Ccy=EUR (unsigned), CdtDbtInd, Dt/Dt <date>
    TxsSummry:
      TtlNtries (NbOfNtries, Sum, TtlNetNtry/Amt + CdtDbtInd)
      TtlCdtNtries (NbOfNtries, Sum)
      TtlDbtNtries (NbOfNtries, Sum)
    Ntry (per batch block, or per tx when batch == false):
      Amt, CdtDbtInd (DBIT for credit transfers, CRDT for direct debits)
      Sts/Cd BOOK, BookgDt/Dt, ValDt/Dt
      AcctSvcrRef (SYNTH-<YYYYMMDD>-<last4>-E<n>)
      BkTxCd/Domn: Cd PMNT, Fmly/Cd ICDT|IDDT, Fmly/SubFmlyCd ESCT|XBCT|ESDD|BBDD
      NtryDtls:
        Btch (batch only): PmtInfId?, NbOfTxs, TtlAmt, CdtDbtInd
        TxDtls (one per tx):
          Refs: MsgId?, PmtInfId?, InstrId?, EndToEndId?, MndtId?
          Amt, CdtDbtInd
          RltdPties: Dbtr/Pty/Nm, DbtrAcct/Id/IBAN, Cdtr/Pty, CdtrAcct/Id/IBAN
            The account owner fills the own side, the counterparty the other.
            For direct debits, Cdtr/Pty adds Id/PrvtId/Othr/Id <creditor_id>
            and SchmeNm/Prtry SEPA.
          RmtInf/Ustrd*
      AddtlNtryInf
    AddtlStmtInf
```
